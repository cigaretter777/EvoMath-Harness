### 1.2 active row 的定义

`rollout_audit.jsonl` 中每条轨迹有多个 `event="step"` 行。终局之后，训练器仍会重复写入 `done=true` 的记录行，但这些行不再产生新的动作。本审计采用：

1. 每条轨迹按 `step_index` 排序；
2. **终局行** = 第一个 `done=true` 的行；若不存在则取最后一行（本数据无此情况）；
3. **active rows** = `step_index <= terminal.step_index` 的行；
4. **inactive rows** = 终局行之后的重复记录行。

因此：

- 终局 `verifier_status`、终局 `reward`、终止原因**每条轨迹只取一次**（首个 done 行）；
- 非法动作率、工具调用数、每条轨迹动作数的分母**只含 active rows**；
- 旧口径把 inactive 行计入分母，等价于给“已经结束的轨迹”继续增加动作尝试，系统性稀释非法动作率。

### 1.3 奖励重算

审计按训练配置重算三种奖励：

```text
R0 = I
R1 = I − 0.10 · min(invalid, 3)
R2 = I · (1 − 0.15 · tool_calls / 4 − 0.10 · tool_seconds / 60)
       − 0.10 · min(invalid, 3)
```

其中 `I` 为终局正确性（0/1），`invalid` 为该轨迹 active rows 中的非法动作数，`tool_calls` 为 active rows 中的工具调用数，`tool_seconds` 为 active 工具调用的累计计费秒数。R2 裁剪到 `[−1, 1]`。

- 因此 active 口径没有漏掉“发生在终局后的新非法动作”；它只是去掉了重复计数。

## 3. 审计 B：R0 奖励均值差异与日志口径

### 3.1 三个均值不是同一个东西

| 组别 | 逐轨迹奖励均值 | 按 update 的 active-row 加权均值 | 日志 `critic/rewards/mean` | 日志 `episode/reward/mean` | 日志 `episode/success_rate` | 差值（行加权−日志 critic） | 差值（逐轨迹−日志 episode） |
|---|---:|---:|---:|---:|---:|---:|---:|
| R0 | 0.298125 | 0.2826391 | 0.28264 | 0.29814 | 0.29814 | −8.5e−7 | −1.5e−5 |
| R1 | 0.305375 | 0.2952520 | 0.29534 | 0.30542 | 0.31132 | −8.8e−5 | −4.5e−5 |
| R2 | 0.2826871 | 0.2761745 | 0.27608 | 0.28260 | 0.29940 | +9.5e−5 | +8.7e−5 |

定义：

- **`critic/rewards/mean`**：verl 的 `metric_utils.py` 先算每条 sequence 的 `token_level_rewards.sum(-1)`，再对 batch 内所有 sequence 取均值。每个 active turn row 是一条 sequence，且都携带该轨迹的终局奖励，所以这个指标**按 active turn 行数加权**：轨迹越长，其终局奖励在均值中的权重越大。日志值又是 50 个 update 的 per-update 均值的等权平均。
- **`episode/reward/mean`**：按 `traj_uid` 去重，每条轨迹只计一次，是**逐轨迹等权**均值。
- **`episode/success_rate`**：逐轨迹正确性均值；对 R0 与 `episode/reward/mean` 相同（二值奖励），对 R1/R2 因惩罚/成本而低于奖励均值。

### 3.2 为什么 R0 是 0.2826 而不是 0.2981

R0 的 correct 轨迹平均 **2.059** 个 active 行，incorrect 轨迹平均 **2.142** 行，`invalid_prediction` 轨迹固定 **4.000** 行。按行加权时：

- 477 条正确轨迹的奖励 1 被重复约 2.06 次；
- 54 条 `invalid_prediction` 轨迹的奖励 0 被重复 4 次；
- 因此行加权均值被拉低到 0.2826，而逐轨迹均值仍是 477/1600 = 0.298125。

这不是奖励计算错误，也不是日志重复计数；它是“按 turn 行加权”与“按轨迹等权”两个指标的定义差异。R1/R2 的残差约 1e−4，量级远小于 R0 的 1.55 pp 口径差，可能来自 per-update 聚合或日志精度；无论其来源如何，都不改变本节结论。

### 3.3 报告应怎么改

- 在 §4.3 表头把“奖励均值”改为“`critic/rewards/mean`（按 active turn 行加权）”，并增加一列“`episode/reward/mean`（按轨迹等权）”。
- 在表下加脚注：R0 的 0.2826 与 477/1600=0.2981 的差异完全来自分母/加权，不是奖励不一致；逐轨迹均值为 0.29814。
- 不要用行加权奖励均值去和“成功率×1.0”做差并解释为惩罚，除非先说明两者的分母不同。

| all-correct | 33 | 33 | 全对组；成本项不被正确性门控乘掉 |
| all-wrong | 180 | 32 | 非零方差来自非法惩罚；成本项被门控乘掉 |
| mixed | 187 | 187 | 正确性差异主导 |

all-correct 组共 33 × 4 = 132 条样本。

### 4.2 all-correct 组的成本变异

| 统计量 | 值 |
|---|---:|
| 有工具次数成本变异的组 | **1 / 33** |
| 有时间成本变异的组 | **33 / 33** |
| 组内奖励标准差 min / median / max | 8.53e−5 / 4.16e−4 / 1.92e−2 |
| 组内时间差 min / median / p75 / max（秒） | 0.125 / 0.584 / 0.754 / 1.214 |
| 时间差 > 0.5 s 的组 | 22 / 33 |

也就是说：**调用次数在训练中几乎没有组内变异（33 个全对组只有 1 个出现 0 次 vs 1 次），但时间成本在每个全对组都有变异。**

### 4.3 归一化后的优势

GRPO 的实现是 `compute_grpo_outcome_advantage`：

```text
Â_i = (R_i − R̄_group) / (s_R_group + ε)
```

`torch.std` 默认 `unbiased=True`，即样本标准差（G−1）；`ε=1e−6`。审计复算：

| 统计量 | 值 |
|---|---:|
| 每组最大 \|A\| 的 min / median / max | **0.968 / 1.344 / 1.500** |
| 132 条样本中 \|A\| > 0.5 | **85** |
| 132 条样本中 \|A\| > 1.0 | **36** |
| 仅保留次数成本时的 median max \|A\| | **0.0**（唯一有次数变异的组为 1.4999） |
| 仅保留时间成本时的 median max \|A\| | **1.334** |
| 实际成本项的 median max \|A\| | **1.344** |

因此：

- **“原始成本折扣只有 3.8%，所以优势很小”在数学上不成立。** 归一化除以的组内标准差与原始差异同量级（中位数 4.16e−4），所以原始差 1e−3 量级会被放大成 O(1) 优势。
- **信号主要来自时间分量，不是调用次数。** 32/33 个全对组只有时间成本变异；把两个分量分别单独保留并重新归一化时，仅次数成本的中位最大 |A| 为 0（只有一个组有 0 次 vs 1 次的差异），仅时间成本为 1.334，与实际 1.344 接近。
- **这不是“成本项完全没有学习信号”。** 更准确的说法是：训练中存在由时间成本形成的 O(1) 归一化优势，覆盖 33/400 个采样组、132/1600 条轨迹；调用次数分量几乎饱和。

### 4.4 时间差异是真实效率还是计时噪声？

现有产物**不能识别**。理由：

1. 每条轨迹只执行一次，没有对同一段代码/同一工具调用做重复执行，无法估计沙箱计时噪声的组内标准差；
2. 训练期 R2 的时间项混合了 Python 沙箱 `execution_time`（1,567 次）与 SymPy worker 进程墙钟（1 次），不是单一计量边界；
3. 评测期 R1 的三次 30 秒超时说明基础设施停滞可以把“工具时间”抬高两个数量级；训练期虽然没有同类超时记录，但不能排除较小的负载波动；
4. 0.125–1.214 s 的组内时间差既可能是不同代码的真实执行差异，也可能是同一量级的沙箱调度噪声；没有重复执行对照，二者不可分。

要真正区分“实测时间差异”与“时间噪声”，需要对同一段代码/同一工具调用做重复执行以估计计时噪声，或在工具返回中分离排队时间与执行时间；本轮只读审计不启动这类新实验。

**结论**：R2 的成本项在训练中**有**归一化后的学习信号，但该信号是否代表“真实效率”、是否被计时噪声主导，尚不能识别。报告不能从“原始奖励差小”推断“没有信号”，也不能从“归一化优势 O(1)”推断“模型因此学会了省时”。前者已被审计否定，后者需要重复计时/消融实验。

### 4.5 优势标准差口径

为确认实现口径，审计用每条轨迹的终局奖励按组重构优势，并与 `train.log` 的 `critic/advantages/max/min` 比较：

- 使用 **G−1**（样本标准差）时，150/150 个 update 在日志三位小数精度上完全一致；最大绝对误差 ≤ 4.6e−4（来自日志舍入）。
- 使用 **G**（总体标准差）时，0/150 个 update 匹配；最大偏差约 **0.232**。

因此本实验实现使用 **G−1**。若开题/论文方法部分写的是 G，需要明确标注“实现采用样本标准差 G−1”，不能两处混用。输出：`advantage_std_check.json`。
