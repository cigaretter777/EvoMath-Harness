## 摘要

本实验研究统一 Python/SymPy 工具环境下，三种轨迹级奖励对 Qwen3-1.7B 数学推理智能体的影响：R0 只用最终答案正确性；R1 增加非法动作惩罚；R2 在 R1 基础上再增加工具调用次数与累计工具时间成本。三组均从同一原始 SFT 检查点独立初始化，使用相同的工具预算、数据顺序、GRPO 超参数和采样规则，各训练 50 个全局更新（每组 1600 条轨迹）。训练完成后，四组在 200 道冻结 MATH 测试题上各生成一条贪心轨迹，使用同一评测器、同一验证器和同一工具后端。

主表结果为：SFT 正确率 56.00%（112/200），GRPO+R0 53.00%（106/200），GRPO+R1 51.50%（103/200），GRPO+R2 54.00%（108/200）。三个预设比较 `R0−SFT`、`R1−R0`、`R2−R1` 的正确率差值分别为 −3.00、−1.50、+2.50 个百分点；双侧精确 McNemar 检验的 Holm 校正 p 值为 0.328、0.549、0.453，均不显著。协议指标方面，R0 相对 SFT 的非法动作率上升 11.42 个百分点（配对 bootstrap 95% CI [+7.39, +15.67]），轨迹截断率上升 4.5 个百分点（[+1.5, +8.0]）；R1 相对 R0 的非法动作率下降 10.19 个百分点（[−14.82, −5.65]），截断率下降 4.5 个百分点（[−8.0, −1.0]）；R2 相对 R1 的非法动作率再降 1.97 个百分点（[−4.84, 0.00]），截断率再降 1.0 个百分点（[−2.5, 0.0]）。R2 的工具调用次数为 0.995 次/题，R1 为 0.990 次/题，差异仅 +0.005（[0.000, +0.015]）；R2 与 R1 的工具时间原始差值为 −0.461 秒/题，但 R1 的均值包含三次连续 30 秒超时（合计 93.069 秒），剔除后 R1 为 0.452 秒/题，R2 为 0.457 秒/题，没有可解释的成本下降。

机制上，R0 的纯结果奖励没有直接约束动作格式，训练后期非法动作率从 1.62% 升到 7.41%，评测中出现 12.42% 非法动作、5.50% 轨迹截断和 3 条 `max_steps` 终止；代表轨迹中模型三次把正确答案写进不可解析的畸形 envelope，最终被计为错误。R1 的非法动作惩罚明显改善了格式，但没有提高正确率；一个原因是工具执行失败（`execution_error`）仍是所有组最常见的工具失败（36–42 次/组），而 R1 并不惩罚“合法调用但代码执行失败”。R2 的成本项未能降低工具使用，是因为工具调用在本数据上饱和于 0 或 1 次：R2 有 199/200 题恰好调用一次、1 题零次，没有任何题达到 2 次以上；成本只对正确轨迹生效，且每条正确轨迹的成本折扣约为 3.8%，在组内近似常数，无法提供“少调用”的排序信号。

本实验的结论必须按单种子、50 轮、200 题、无正式非劣效设计的范围来读：**已完成三组独立训练、统一评测和预设配对分析；发现并修复了一个验证器集合比较崩溃；支持奖励塑形对协议指标有效；不支持正确率提升、工具成本下降或非劣效结论。** 报告末尾分别列出“已完成 / 未完成 / 发现问题 / 不能支持的结论”。

## 1. 研究问题与论文定位

### 1.1 研究背景

论文关注工具增强数学推理智能体的轨迹级奖励设计。此类智能体在一次答题中可能执行多轮“思考—工具调用—观察—再思考”，最终给出答案。若训练奖励只看最终答案是否正确，策略可能在提高答案正确率的同时学会冗长、格式不稳定或滥用工具的行为；若加入非法动作惩罚或工具成本，理论上可以抑制这些行为，但也可能压缩必要的探索、损害正确率。

本实验是论文中期前的**小规模对照预实验**，目的不是给出最终性能结论，而是验证：

1. 三种奖励能否在统一工具环境和统一预算下被正确实现、独立训练和统一评测；
2. 奖励塑形首先改变哪些可观测行为；
3. 在当前算力与数据规模下，正确率差异是否足以支持后续更大规模实验；
4. 实验流程、验证器、沙箱和统计口径是否存在会在正式研究中放大问题的方法学缺陷。

### 1.2 三个研究问题

| 编号 | 研究问题 | 对应奖励 |
|---|---|---|
| RQ1 | 只用最终答案正确性做 GRPO，会如何改变工具使用行为与正确率？ | R0 |
| RQ2 | 加入非法动作惩罚，是否减少非法动作/截断，并改善正确率？ | R1 |
| RQ3 | 在 R1 基础上加入工具调用次数与累计时间成本，是否进一步降低工具使用而不损害正确率？ | R2 |

### 1.3 本实验能回答与不能回答的问题

**能回答：**

- 在固定预算、固定数据顺序、固定评测协议下，三种奖励实现是否可运行、可复现、可审计；
- 奖励项是否改变了非法动作率、截断率、工具调用次数、工具时间等**直接目标指标**；
- 正确率的点估计方向、配对不一致样本和置信区间是什么；
- 当前样本量下哪些差异无法排除、哪些结论不能下。

**不能回答：**

- 三种奖励在更大模型、更长训练、多随机种子下的长期排序；
- 任一 GRPO 组是否“非劣于”SFT（本实验没有预设非劣效界值，也没有相应功效）；
- 奖励项通过何种梯度路径影响正确率（本实验没有做梯度分解或消融）；
- 在工具调用次数大于 1 的任务分布上，R2 的成本项是否有效（本数据上工具调用饱和于 0/1）；
- SFT 训练数据与 RL 训练/测试数据之间是否存在完全独立的污染审计（只审计了 train/dev/test 三者之间的重叠）。

### 1.4 与开题方案/设计文档的对应

| 设计文档要素 | 本实验的落地方式 | 证据位置 |

### 2.3 统一工具预算与动作协议

| 预算/协议项 | 值 | 说明 |
|---|---:|---|
| 最大环境步数 | 6 | 每步最多一个动作 |
| 最大工具调用次数 | 4 | 所有工具共享 |
| 累计工具时间预算 | 60 s | Python 与 SymPy 共享 |
| 单次工具调用超时 | 30 s | 超时按请求额度计入工具时间 |
| 单次观察截断 | 8,000 字符 | 截断单独计数，不与生成截断混淆 |
| 最大生成长度 | 2,048 token/回合 | 达到上限单独计为长度截断 |
| 最大提示长度 | 4,096 token | 超过时显式 `CONTEXT_OVERFLOW`，不静默截断 |
| 系统提示版本 | `agent-v2` | 四组完全相同 |
| 工具 | `python`、`sympy` | 两类工具共享累计时间预算 |

动作协议为：每回合必须且只能输出一个 `<tool_call>{"name":"python"|"sympy","arguments":...}</tool_call>` 或一个 `<final>{"answer":"..."}</final>`。工具观察以 `tool` 角色追加到对话历史；历史保留，超过 4,096 token 时按显式上下文溢出终止。`max_python_seconds=0.0` 表示关闭旧版的“仅 Python 计时”上限，**不是**把 Python 执行时间设为零；统一预算由 `max_tool_seconds=60` 控制。

**非法动作与工具失败的区分。** 解析失败、参数校验失败属于非法动作（`action_parse_error` / `tool_validation_error`），不产生工具执行时间；工具调用格式合法但代码运行失败（`execution_error`）或超时（`timeout`）属于工具失败，不计为非法动作。这一区分对解释 R0 的格式漂移和 R1 的惩罚范围至关重要。沙箱不可用（`sandbox_unavailable`）既不计非法动作，也不计工具时间，而是记为基础设施错误并触发评测暂停/重跑。

### 2.4 三种轨迹奖励

记：

- \(I(\tau)\in\{0,1\}\)：轨迹最终答案是否正确；
- \(N_{\text{invalid}}\)：轨迹中非法动作尝试数；
- \(N_{\text{tool}}\)：轨迹中实际执行的工具调用次数；
- \(T_{\text{tool}}\)：轨迹累计工具执行时间（秒）；
- 参数 \(\mu=0.10\)，\(K=3\)，\(\alpha=0.15\)，\(\beta=0.10\)，\(B_{\text{tool}}=4\)，\(B_{\text{time}}=60\) s。

| 组别 | 奖励定义 | 版本 |
|---|---|---|
| R0 | \(R_0=I(\tau)\) | `r0-v2-unified-tool-time` |
| R1 | \(R_1=I(\tau)-\mu\min(N_{\text{invalid}},K)\) | `r1-v2-unified-tool-time` |
| R2 | \(R_2=I(\tau)\left[1-\alpha\frac{N_{\text{tool}}}{B_{\text{tool}}}-\beta\frac{T_{\text{tool}}}{B_{\text{time}}}\right]-\mu\min(N_{\text{invalid}},K)\) | `r2-v2-unified-tool-time` |

所有版本最后执行 `clip(·,−1,1)`。关键实现口径：

- 非法动作惩罚不受正确性门控；R2 的工具次数/时间成本**只对正确轨迹生效**，错误轨迹不扣工具成本；
- 工具时间按实际计费：Python 优先使用 SandboxFusion 返回的 `execution_time`，超时按请求额度计入；SymPy 在独立 worker 进程中用 `perf_counter()` 在两侧计时；安全拒绝属于“未执行”，不计时；
- 配置 `use_invalid_action_penalty=False`，关闭上游对非法动作的重复惩罚，避免 R1/R2 的显式惩罚被二次叠加；
- 奖励配置哈希：R0 `8e6b5c98f7c0f5dc096ac4f787449e63d538aba315ce2dbdb23d9f7bcc98efe1`，R1 `35a788d95ff3b6661a00f3e717b1e17097619490f9c06e4da7039216dea06535`，R2 `5cdf9218d7ace71781aea5e263277edde846d453db53b98661c0c08ac4e99a87`。

训练使用 FSDP 和 bf16；vLLM rollout 的 V1 前缀缓存被显式关闭（`enable_prefix_caching=False`），因为同一题目的提示在同一批次内重复 4 次时，前缀缓存会导致可解析率明显下降。该修正对三组完全相同。

### 2.6 训练调度与采样

400 个 prompt 槽位 = 50 个全局更新 × 8 个槽位；每个槽位有 4 条 rollout，因此每组 1,600 条训练轨迹。200 道训练题在 400 个槽位中各出现恰好 2 次。开发集 50 题只用于冷启动门，不参与模型选择；测试集 200 题在训练期间从未使用。

三组共享同一份轮次表与数据种子，但各自拥有独立的优化器、训练状态、RNG 状态和输出目录。共享随机种子不构成权重或状态传递；三组可视为同一初始化下的三个独立训练实例。

### 2.8 统计方法

- **主表正确率**：分母固定为 200；预算耗尽、无最终答案、上下文溢出、验证器判错均计为未答对；不做结果插补。
- **非法动作率**：总非法动作数 / 总动作尝试数；分母为 0 时报告 NA，绝不写成 0。实际四组分母分别为 401、451、405、400，均非 0。
- **轨迹截断率**：至少有一次模型输出达到 2,048 token 上限的轨迹数 / 200。上下文溢出和 observation 截断另行统计，不混入该列。
- **配对正确率比较**：`R0−SFT`、`R1−R0`、`R2−R1`；双侧精确 McNemar 检验，报告 b01（前者错、后者对）与 b10（前者对、后者错）；Holm 校正覆盖 3 个预设比较。
- **置信区间**：10,000 次配对 percentile bootstrap，按 200 个题目索引重采样；所有组、所有比较共享同一组重采样索引；seed 20261022；重采样索引 SHA-256 为 `2069a334eaa454758376e24bf8c4a84275cd715098d7189eb71475110bb63364`。
- **非法动作率 bootstrap**：每次重采样重新计算“总非法动作数 / 总动作尝试数”；同时记录分母为 0 的重采样次数。实际所有比较的零分母重采样次数均为 0。
- **工具次数/时间/截断率差值**：同样使用配对 bootstrap，仅作补充描述，不另做多重校正。
- **奖励诊断**：四组轨迹都用 R0/R1/R2 三种定义离线重新评分，仅用于诊断，不作为组间因果排名。
- **不作正式非劣效检验**：没有预设非劣效界值，也没有相应样本量/功效设计；因此 p>0.05 不能解读为“无差异”或“非劣效”。

## 3. 实现修正、冻结与独立性核验

### 3.1 正式训练前的实现修正

在正式训练前，冷启动与 2 步真实 GRPO 冒烟暴露了以下问题。所有修正对 R0/R1/R2 三组完全相同；作废冒烟目录原样保留，仅作诊断证据，不用其检查点初始化正式训练。

| 问题 | 根因 | 修正 | 验证证据 |
|---|---|---|---|
| 首轮 32 条轨迹出现 23 条非法动作，工具调用仅 8 次 | 上游 `preprocess_single_sample` 把完整观察压成单条 `user` 消息，丢失 SFT 使用的 `system`/`user`/`assistant`/`tool` 角色 | `MathRolloutManager.build_chat_obs()` 返回结构化消息；`apply_structured_chat_patch()` 在 `obs['chat']` 存在时按 chat template 渲染 | 修正后 `raw_prompt_ids` 与 `tokenizer.apply_chat_template([system,user], add_generation_prompt=True)` 完全一致；相关单测通过 |
| 训练 rollout 生成崩坏为多语言/emoji 混杂文本 | 训练 vLLM 的 `top_p=1.0, top_k=-1` 与冷启动实际生效的 `top_p=0.95, top_k=20` 不一致 | 四个 GRPO 配置统一为 `temperature=1.0, top_p=0.95, top_k=20` | 冷启动与训练采样规则一致；仍不足以单独消除退化 |
| 对齐采样后首回合仍只有 10/32 可解析 | vLLM V1 前缀缓存遇到同批次重复提示（同题 4 条 rollout）时退化；上游硬编码 `enable_prefix_caching=True` | `apply_vllm_prefix_cache_patch()` 允许显式配置；三组正式配置设 `enable_prefix_caching=False` | 四组生成栈对照：重复提示 + 前缀缓存 11/32 可解析；关闭后 30/32；最终 2 步冒烟 128/128 可解析 |
| 长轨迹在第 3 回合因 `sequence_length=4515 > 4096` 整批崩溃 | 缺少显式上下文溢出终止；`data.truncation` 为 `error` | 固定 `max_prompt_length=4096`；每回合追加动作/观察后计算下一轮提示 token；超限置 `CONTEXT_OVERFLOW`；已产生 `<final>` 时保留 final 奖励并仅记录溢出标志 | 上下文溢出单测；正式训练/评测均记录 `context_overflow`，无静默截断 |
| 组内优势按“回合行数”加权，长轨迹被重复计入 | 上游默认 `compute_mean_std_cross_steps=True` | 启动时注入 `compute_mean_std_cross_steps=False`，每个 `(uid, traj_uid)` 只贡献一次终局奖励 | `tests/unit/training/test_advantage_normalization.py`；三组一致 |
| 非法动作可能被上游和显式奖励重复惩罚 | 上游 `apply_invalid_action_penalty` 默认开启 | 三组配置统一 `use_invalid_action_penalty=False` | 配置与解析后参数一致；R1/R2 只保留显式惩罚 |
| 默认 logger 尝试连接 wandb，首次启动在初始化阶段退出 | `trainer.logger=['console','wandb']` 且无 API key | 三组统一 `trainer.logger=["console"]` | 失败发生在任何 rollout 之前，无检查点；修正后正常启动 |
| 5 个完整 FSDP 检查点无法同时保留 | 单组 7.9 GiB，磁盘不足 | `max_actor_ckpt_to_keep=1`；每次保存后归档 LoRA 适配器到 `adapters/step_NN` | 15 份适配器 + 3 份最终检查点；SHA-256 清单齐全 |

### 5.2 首次评测（v1）的验证器崩溃与修复

**v1 运行**：2026-10-22T19:40:00Z 启动，输出目录 `evaluation/formal_unified_tool_eval_20261023/`，组顺序 SFT → R0 → R2 → R1。19:48:20Z 在 SFT 第 60 题 `math:45e5f7656e796fc9615c` 暂停，前 59 条 SFT 轨迹有效。

**触发**：模型回答 `x \in (0, 36)`，参考为 `(0,9) \cup (9,36)`。`latex2sympy` 把预测解析为 `Eq(x, Interval.open(0,36))`，把参考解析为 `Union(Interval.open(0,9), Interval.open(9,36))`。旧 `_relation_signature` 无条件计算 `lhs - rhs`，对 `Symbol - Interval` 抛出：

```text
TypeError: unsupported operand type(s) for -: 'Symbol' and 'Interval'
```

异常逃出 `compare_expressions`，worker 报告 `internal_error`；重试一次仍复现。同类问题也会出现在 `(p,q) = (1,1)` 的 `Tuple - Tuple` 上。

**修复**（只改 `src/adaptive_math/verifier/symbolic.py` 的结构比较路径）：

1. `_relation_signature` 捕获非算术操作数错误（`TypeError`、`ValueError`、`AttributeError`、`ArithmeticError`、`NotImplementedError`），返回 `None`，让结构比较继续；
2. `Interval`、`Union`、`FiniteSet` 等集合答案用对称差比较；无法判定空集时返回 `invalid_prediction`，不猜测；
3. `Eq(symbol, Set)` 或 `Contains(symbol, Set)` 按目标集合比较；变量侧必须是单一 `Symbol`，避免把 `x^2 \in S` 误当成集合 `S`；
4. 元组等式不再崩溃，落入既有结构比较路径。

### 6.2 三个预设配对比较：正确率

b01 = 前者（treated）错、后者（baseline）对；b10 = 前者对、后者错。OR = b01/b10。置信区间为配对 percentile bootstrap，Holm 校正覆盖 3 个预设比较。

| 对比（前者−后者） | b01 | b10 | Δ正确率（pp）[95% CI] | OR | McNemar p | Holm p |
|---|---:|---:|---|---:|---:|---:|
| GRPO+R0 − SFT | 2 | 8 | −3.00 [−6.00, 0.00] | 0.250 | 0.109375 | 0.328125 |
| GRPO+R1 − GRPO+R0 | 4 | 7 | −1.50 [−4.50, +1.50] | 0.571 | 0.548828 | 0.548828 |
| GRPO+R2 − GRPO+R1 | 8 | 3 | +2.50 [−0.50, +6.00] | 2.667 | 0.226562 | 0.453125 |

读法：

- **R0−SFT**：点估计 −3.00 pp，但 95% CI 上限为 0，McNemar p=0.109，Holm p=0.328；不能宣称 R0 降低了正确率，也不能宣称 R0 不降低正确率。不一致样本只有 10 对（2 对 R0 对/SFT 错，8 对 SFT 对/R0 错）。
- **R1−R0**：点估计 −1.50 pp，CI [−4.50, +1.50]，Holm p=0.549；没有正确率改善的证据，也没有证据表明存在损害。
- **R2−R1**：点估计 +2.50 pp，CI [−0.50, +6.00]，Holm p=0.453；方向略正，但区间跨 0 且上限仅 6 pp，不能视为收益。

**统计解释边界**：200 题、二分类、配对设计下，不一致对数只有 10–11 对，正确率差值的 95% CI 宽度约 6–7 pp。当前样本只能排除较大的差异，不能排除小到中等差异；未做正式非劣效设计，因此不能把 p>0.05 写成“无差异”或“非劣效”。

### 6.6 代表性轨迹

题目 `math:0940ea16d9b72903d6f4`（Level 4 Algebra）：

> Four distinct integers \(a\), \(b\), \(c\) and \(d\) have the property that when added in pairs, the sums 16, 19, 20, 21, 22, and 25 are obtained. What are the four integers in increasing order? (place a comma and then a space between each integer)

参考答案：`7,9,12,13`。

**SFT（正确）**：第 1 回合生成正确的 SymPy 代码，建立 6 个两两和方程并求解，工具返回 `[7, 9, 12, 13]`；第 2 回合输出 `<final>{"answer":"7, 9, 12, 13"}</final>`。2 步、1 次工具、0 非法动作，判对。

**R2（正确）**：与 SFT 在该题上的原始输出**逐字相同**：同一段求解代码、同一工具结果、同一 final。2 步、1 次工具、0 非法动作，判对。这说明 R2 并非在所有题上都改变了策略；在该题上它与 SFT 的行为完全一致。

**R1（错误）**：第 1 回合代码结构基本正确，但排序写成：

```python
integers = sorted(solution[a], solution[b], solution[c], solution[d])
```

`sorted` 被传入 4 个位置参数，运行时报 `TypeError: sorted expected 1 argument, got 4`。第 2 回合没有修复代码，而是直接输出 `<final>{"answer":"1, 2, 3, 10"}</final>`，判错。2 步、1 次工具、0 非法动作。该例说明：**合法但执行失败的工具调用不在 R1 的非法动作惩罚范围内**，模型在工具失败后可能直接猜测。

**R0（错误，`max_steps`）**：第 1 回合代码把每个两两和写成 `a + b + c + d - sum`（代码中把 `sum` 用作循环变量），方程构造有误；执行时报 `AttributeError: 'list' object has no attribute 'values'`。第 2 回合模型转向一个与本题无关的 SymPy 计算 `(1/2)^4`，被工具参数校验拒绝（`tool_validation_error`）。第 3 回合生成 1,101 token 的正确推理文本，但没有输出 `<tool_call>` 或 `<final>`，被判 `invalid_envelope`。第 4–6 回合每回合恰好 26 token，内容为：

```text
<think>

<>
<final>{"answer":"7, 9, 12, 13"}</final>
</tool_call>
```

三次都被判 `invalid_envelope`。最终 `max_steps` 终止，`final_answer=None`，判错；共 6 步、1 次工具调用、5 次非法动作。**正确答案在畸形 envelope 中出现了三次，但评测器无法解析，R0 的结果奖励也无法区分“格式错误但内容正确”和“内容错误”。** 这是 R0 协议漂移的典型样本，也是“答案存在但不可达”的直接证据。

#### 6.7.3 奖励离线重算

对四组各抽 5 条轨迹（3 条正确 + 2 条错误，按 task_id 排序），共 20 条 × 3 种奖励 = 60 个检查点，用训练同一奖励公式离线重算，**60/60 完全一致，0 处不匹配**。输出：`analysis/reward_recompute_20.json`，SHA-256 `f82909f3b185d95278b3a70855234e5d185e4a507c5cc89f734c368b7e91d5d0`。重算公式：

```python
if variant == "r0":
    v = I
elif variant == "r1":
    v = I - 0.10 * min(invalid, 3)
else:  # r2

v = max(-1.0, min(1.0, v))
```

该检查验证的是评测器存储的奖励分项与训练奖励函数一致，不是新的结果指标。

## 7. 讨论

### 7.1 R0：结果奖励导致协议漂移，但正确率损害未被统计确认

R0 只有 \(I(\tau)\)，没有直接约束动作格式。训练期非法动作率从 1.62% 升到 7.41%，评测期达到 12.42%；截断率 5.50%；3 条轨迹以 `max_steps` 终止；生成 token 总数比 SFT 高 61.2%。代表轨迹显示，R0 在工具失败后转向无关计算，随后把正确答案反复写进不可解析的 envelope，最终被判错。

这组证据足以说明“仅结果奖励会让协议行为变差”，但**不足以说明它降低了正确率**：R0−SFT 的点估计是 −3.00 pp，McNemar p=0.109，Holm p=0.328，95% CI 上限为 0。正确的表述是“R0 造成了明确的协议漂移，正确率点估计偏低但差异不显著”。

### 7.2 R1：非法动作惩罚命中了目标指标，但没有转化为正确率

R1 的非法动作率从 R0 的 12.42% 降到 2.22%（相对下降约 82%），截断率从 5.50% 降到 1.00%，训练期非法动作率保持在 1.22%–2.94%。这说明惩罚项确实在优化它直接惩罚的行为，且没有出现“压非法动作导致大量空答案/崩溃”的迹象（R1 有 198 条 final，2 条无最终答案）。

但 R1 的正确率点估计比 R0 低 1.50 pp（Holm p=0.549），没有证据表明格式改善带来了正确率收益。一个与数据一致的解释是：工具执行失败仍是 R1 的主要失败来源（42 次 `execution_error` + 3 次超时），而 R1 不惩罚“合法调用但代码执行失败”；代表轨迹中 R1 在 `TypeError` 后直接猜测答案。R1 的惩罚改善了“会不会把动作写坏”，但没有改善“代码写错后会不会恢复”。这一解释是机制假设，本实验没有做恢复行为的专项标注，不能当作已证实的因果链。

### 7.3 R2：成本项没有降低工具使用，原因是工具使用已饱和且成本被正确性门控

R2 的协议指标最干净：非法动作率 0.25%、截断率 0、200/200 正常 final。但：

1. **工具调用饱和**：四组都只有 0 或 1 次调用，没有任何题达到 2 次以上；预算允许 4 次，但策略没有接近上限。成本项没有可压缩的调用次数。
2. **成本只对正确轨迹生效**：错误轨迹的工具调用不扣成本，因此“错误且浪费工具”不受惩罚；R2 无法教会模型在失败轨迹上少调用。
3. **正确轨迹的成本近似常数**：正确轨迹几乎都恰好 1 次调用，工具次数成本约 0.0375、时间成本约 0.00045，总折扣约 3.8%；组内差异极小，不能改变轨迹排序。
4. **时间成本量级太小**：\(\beta T/B_{\text{time}}\) 在 0.3–0.5 秒量级只产生 \(10^{-4}\) 量级的奖励差；与正确性（1.0）和非法惩罚（0.1/次）相比可以忽略。

因此，R2 没有降低工具调用次数（0.995 vs 0.990，实际是 R2 略多一次总调用），也没有可解释的工具时间下降。该结论只适用于本实验这种“工具使用饱和、成本门控于正确性”的设置，不能外推为“工具成本奖励普遍无效”。

### 7.4 正确率差异不显著：样本量与设计限制

三个预设比较的 Holm p 值均大于 0.05，正确率 95% CI 宽度约 6–7 pp。当前设计：

- 只有 200 道测试题，配对不一致样本只有 10–11 对；
- 只有 1 个训练种子、50 个全局更新；
- 没有预设非劣效界值，也没有按最小感兴趣差异做功效分析；
- 训练分布与测试分布不同（测试更容易、更偏代数）。

因此，本实验的正确率结果应表述为“**未检出统计显著差异**”，而不是“三组等价”“R1/R2 不损害正确率”或“SFT 优于 GRPO”。SFT 的 56.0% 只是四组中的最高点估计；本实验没有预设 SFT vs R2 的比较，不能据此宣称 SFT 优于 R2。

### 7.5 训练指标与评测指标的差距

训练成功率（29.8%–31.1%）明显低于测试正确率（51.5%–56.0%）。这不是矛盾：训练成功率是在训练分布、随机采样、每题 4 条 rollout 上计算的；测试正确率是在更容易、更偏代数的测试分布上、贪心解码、每题 1 条轨迹上计算的。两者不可直接比较，也不能用训练成功率的上升/下降推断测试泛化。

训练步时 R0 明显更长（314 s vs 225/217 s），与 R0 更长的响应、更多非法动作和更多回合一致；但步时包含工具等待和 rollout 长尾，不是纯计算效率指标。R2 的步时最短，不能单独解释为“R2 更高效”，因为其轨迹更短、工具失败模式也不同。

### 7.6 对论文与后续实验的含义

1. **协议指标是当前最可靠的效应**：R1/R2 的惩罚项确实改变了非法动作率和截断率，且方向与设计一致；这些可以作为中期答辩的实证结果。
2. **正确率需要更大规模或多重种子才能下结论**：当前点估计差异小、区间宽；若论文要主张正确率收益/非劣效，需要预先设定界值、增加种子和测试题量。
3. **R2 的成本设计需要改任务或改门控**：若要让成本项可检验，应使用需要多次工具调用、工具调用有明显冗余的任务分布；或把成本应用到所有轨迹（不按正确性门控），并单独消融 \(\alpha\) 与 \(\beta\)。本实验没有做这些变体，不能替论文提前下结论。
4. **工具执行成功率是更直接的杠杆**：R1/R2 都没有减少 `execution_error`（36–42 次/组），而这是最常见的工具失败。后续若要提升正确率，优先研究代码生成/执行恢复，而不是继续加大格式惩罚。
5. **验证器与沙箱是方法学风险点**：集合比较崩溃和五次沙箱瞬断都发生在正式评测中；正式论文实验应把验证器模糊测试、沙箱健康检查和暂停/恢复协议纳入标准流程。

## 8. 有效性威胁与局限

### 8.1 统计与设计

- **单训练种子**：三组各只训练 1 次，无法估计训练随机性；所有 CI 只反映 200 题抽样不确定性，不包含种子方差。
- **样本量小**：200 题、二分类、配对不一致 10–11 对；对小于约 6–7 pp 的差异几乎没有分辨力。
- **无正式非劣效设计**：没有预设非劣效界值，不能声称“非劣效”或“等价”。
- **多重比较**：正确率用 Holm 校正 3 个预设比较；非法动作率/工具指标只用 bootstrap 区间描述，未另做多重校正，不能把“区间不含 0”当作与正确率同等级的确认性结论。
- **测试分布偏移**：测试集比训练集容易、更偏代数；不能外推到同分布或更难题目。
- **无外部测试集**：只用一个 200 题 MATH 测试集，没有跨数据集验证。

### 8.2 数据与污染

- train/dev/test 三者之间 task_id 与题面重叠为 0，测试候选经过 8 词 shingle containment ≥0.8 的既有权重题面过滤；但**没有独立审计 SFT 数据与 RL 训练/测试数据的污染**，不能声称完全无污染。
- 测试题是从过滤后的 3,467 条候选中抽取的 200 条，不是从完整 MATH 测试分布随机抽样；难度/主题分布与训练集不同。
- 开发集只用于冷启动，没有用于超参数选择；这避免了开发集泄漏，但也意味着没有独立的模型选择集。

### 8.3 验证器

- 正式评测前发现并修复了集合/集合隶属/元组比较崩溃；修复只改结构比较路径，但训练期已用旧验证器完成，9 条 `internal_error` 事件中有 2 条修复后应判正确（均在 R1）。训练未回溯重跑。
- `invalid_prediction` 一律按未答对计；验证器对某些等价格式可能覆盖不足，绝对正确率可能被低估。该误差对四组使用同一验证器，但不同组的答案格式分布不同，不能保证误差完全对称。
- 解析器只容忍 `unclosed_think` 与 `bare_final_scalar`，不容忍反引号等格式；冷启动中已观察到反引号错误。绝对正确率受解析规则影响，组间比较使用同一规则。

### 8.4 沙箱与工具计时

- 评测期间发生 5 次沙箱瞬断（SFT 2 次、R1 3 次），每次保留无效行、探针恢复后重跑；未更换后端、未选择性删除。后端地址/端口不变，但 SSH 隧道 PID 在最后一次暂停时由 96031 变为 135060，说明通道重建。
- R1 三次 30 秒超时是基础设施停滞，不是模型计算成本；主表按协议保留，敏感性分析剔除后 R2 无工具时间优势。工具时间跨组串行测量，受沙箱负载/通道状态影响，不能当作精确的因果成本。
- 沙箱不可用不计非法动作、不计工具时间；这可能使少数轨迹的“动作尝试”分母略低，但无效行不进入主分析。

### 8.5 训练/评测实现

- 训练用 vLLM 随机采样（temperature 1.0、top_p 0.95、top_k 20），评测用 HF 贪心；这是有意的训练/评测差异，四组一致，但绝对性能不能直接与训练指标对齐。
- 训练期 V1 前缀缓存被关闭；这是为保证重复提示下的可解析率，三组一致。该修正可能改变训练吞吐，但不改变奖励或数据。
- R2 的成本项在正确性门控下近似常数；本实验无法区分“成本项本身无效”与“当前任务分布没有可压缩的工具调用”。这是设计覆盖不足，不是奖励实现错误。
- 训练峰值显存 22.92 GB 来自冒烟实测；正式训练日志的最大 reserved 值未作为硬指标报告，单卡 24 GB 下未发生 OOM。
- tokenizer 在训练和评测日志中均出现 `incorrect regex pattern` 警告。四组使用同一 tokenizer 与同一警告，组间比较不受影响；但绝对 token 化/正确率可能受该已知问题影响，未在本实验中修复。

### 8.6 结果解释

- 奖励诊断是离线重评，不是各组优化目标的因果比较；不能用来给奖励函数排序。
- 训练成功率、奖励均值、步时是训练 rollout 指标，不是测试泛化指标。
- 代表性轨迹是单题示例，用于说明机制，不是组间效应的统计证据。
- 本报告没有做梯度分解、注意力分析或代码执行错误的逐条人工标注；“R1 未改善恢复行为”“R2 成本被门控”是机制假设，需后续实验验证。

## 9. 结论

### 9.1 已完成

- 从同一原始 SFT 检查点独立完成 R0/R1/R2 三组各 50 个全局更新的 GRPO 训练；每组 1,600 条训练轨迹，共 4,800 条。
- 三组最终检查点、适配器、50 个 rollout dump、50×32 条 reset 审计均通过核验；`verify_group_complete` 全部返回 `[]`。
- 完成 4 组 × 200 题 = 800 条统一贪心评测；四组使用同一评测器、同一修复后验证器、同一工具后端、同一预算和解码协议。
- 完成主表、Wilson 区间、三个预设配对比较、精确 McNemar、Holm 校正、10,000 次配对 bootstrap、非法动作率零分母检查、工具/截断补充差值、奖励离线重算和敏感性分析。
- 完成冷启动门（80 条）、最终代码 2 步真实 GRPO 冒烟（128/128 可解析）、FSDP 检查点恢复和 PEFT 适配器重载验证。
- 发现并修复验证器集合比较崩溃；v1 评测作废、v2 全量重跑；补丁、备份、回归测试和审计记录齐全。
- 本报告及所有结果产物已落盘；未启动新的训练或评测。

### 9.2 未完成

- 没有多训练种子（≥3–5），无法估计训练随机性；所有区间只覆盖题目抽样。
- 没有正式非劣效性设计、界值或功效分析；不能下“非劣效/等价”结论。
- 没有外部测试集或跨数据集验证；只有一个 200 题 MATH 测试集。
- 没有 SFT 数据与 RL 训练/测试数据的独立污染审计。
- 没有在验证器修复后回溯重跑三组训练；训练期 2 条假阴性保留为限制。
- 没有做 R2 的 \(\alpha\)/\(\beta\) 分离消融、成本门控变体、或多工具调用任务上的成本实验。
- 没有对工具执行失败后的恢复行为做逐条人工标注或专项分析。
- 没有做梯度分解、优势分布分解或奖励项的因果路径分析。

### 9.3 发现问题

- **验证器集合比较崩溃**：`x \in (0,36)` 触发 `Symbol - Interval` TypeError；已修复并加回归测试；v1 评测因此作废，v2 全量重跑。
- **训练期验证器假阴性**：9 条 `internal_error` step 事件、涉及 8 条轨迹，其中 2 条修复后应判正确（均在 R1）；训练未回溯重跑。
- **R0 协议漂移**：训练非法动作率 1.62%→7.41%，评测非法动作率 12.42%、截断率 5.50%、3 条 `max_steps`；代表轨迹出现正确答案被畸形 envelope 包裹三次而判错。
- **R1 工具执行失败未覆盖**：R1 将非法动作率降到 2.22%，但仍有 42 次 `execution_error` + 3 次超时；代表轨迹在 `TypeError` 后直接猜测。
- **R2 成本项未产生可测的工具节省**：工具调用饱和于 0/1，成本只对正确轨迹生效且约 3.8% 折扣；调用次数 0.995 vs 0.990，工具时间差异由 R1 超时伪影主导。
- **沙箱不稳定**：5 次瞬断、3 次 30 秒超时；均保留证据、同后端恢复、未选择性删行。
- **tokenizer regex 警告**：训练和评测均出现，未修复；四组一致，但绝对结果可能受影响。

### 9.4 不能支持的结论

- **不能**说 R0/R1/R2 提升了正确率；三个预设比较的 Holm p 值均 >0.05。
- **不能**说 R1 通过减少非法动作提升了正确率；非法动作率确实下降，但正确率点估计为 −1.50 pp，差异不显著。
- **不能**说 R2 降低了工具调用次数或工具时间；调用次数几乎相同，工具时间差异由 R1 超时伪影造成，剔除后无差异。
- **不能**说任一 GRPO 组非劣于 SFT；没有非劣效界值、没有相应功效，且点估计均低于 SFT。
- **不能**说 SFT 显著优于所有 GRPO 组；SFT 只是点估计最高，未做预设的 SFT vs R2 比较，R0−SFT 也不显著。
- **不能**说 R0 显著损害了正确率；点估计 −3.00 pp，但 p=0.109、Holm p=0.328、CI 上限为 0。
- **不能**说“奖励函数排序”或“R2 奖励最好/最差”；离线诊断不是因果比较，且各组优化目标不同。
- **不能**说“R2 的成本奖励普遍无效”；本实验只在工具使用饱和、成本门控于正确性的设置下观察到无工具节省，不能外推到多工具任务或其他成本参数。
- **不能**说“完全无数据污染”或“结果可外推到完整 MATH 分布”；只完成了 train/dev/test 三者之间的重叠审计和测试候选的既有权重题面过滤。
- **不能**说“长期稳定有效”；只有单种子、50 轮、200 题的一次预实验。
