# 数学推理智能体工具反馈与错误恢复：探索性验证实验报告

日期：2026-10-14（Asia/Shanghai）  
状态：执行设计；尚未运行，尚无本轮研究结论  
适用项目：EvoMath-Harness / Adaptive-Solver-main  
用途：交给执行 agent 开展小规模诊断，为硕士开题确定研究问题。本文不是新强化学习方法有效性的证明。

## 1. 目标与研究边界

核心问题：在有效工具交互中，模型是否存在值得研究的错误后行动调整困难？详细工具反馈与简单修复提示能否改善同一错误状态之后的最终求解？

本轮不训练模型、不扫描预算、不人为注入错误、不构建新平台。正确解题为主要目标，调用和生成成本为辅助指标。结果允许支持、否定或暂不能判断候选问题，不以取得正结果作为完成条件。

当前已有的零调用实验仅说明当时模型、生成与解析组合未形成有效工具交互，不能作为反馈利用困难的证据。不得将其与本轮合并成同一配置的结果。

待检验的三项命题：

- H1（问题覆盖）：自然轨迹中存在工具执行错误，并存在错误后恢复失败或重复错误。
- H2（反馈作用）：在相同错误状态上，保留详细反馈比只提供失败标记能改善最终正确率。
- H3（简单改善空间）：在相同错误状态上，固定修复提示比原始反馈续跑能改善最终正确率。

H2/H3的差异反映整个观测干预的效果，不能自动解释为纯语义机制、RL缺陷或新算法必要性。详细反馈与简短失败标记长度不同；不匹配长度的本轮不宣称隔离了信息内容与长度的作用。

## 5. 阶段A：交互有效性门槛

先做独立、确定性的协议测试：合法调用、执行成功、可复现代码错误、错误观测回传、最终作答。这些合成测试只验证工程接口，不计入自然错误统计。

随后10题×2次采样=20条自然轨迹。记录调用执行数、模型可见反馈、解析失败、真实长度触顶和各终止原因。

A通过条件（操作门槛，不是统计结论）：

1. 至少5/20条轨迹执行过合法工具调用；这是本次诊断池可用性的筛选门槛，不代表理想策略应多调用。
2. 人工核查至少3条包含“调用—反馈—后续生成”的完整轨迹，输入与日志一致。
3. 模型调用/沙箱服务异常为0；服务故障与模型代码错误分开。
4. action_parse_error步数/生成步数≤10%；未产出完整合法动作的长度触顶步数/生成步数≤10%。不得用固定finish_reason判截断。
5. 无隐藏标签泄漏，生成seed真实生效，答案判定冒烟测试通过。

A未通过：不运行B/C。允许一次针对已定位基础问题的修正后重跑A，保存前后配置与结果；仍不通过即输出 `BLOCKED_VALIDITY`，不循环扩大调参。若修正涉及生成长度，仅针对证实的长度问题调整，例如2048→4096，并重新估算资源。模型选择不得依据B/C结果。

A通过后冻结模型、配置、协议和数据哈希，生成 `protocol.lock.json`。B/C任何变化必须停止，建立新版本，不混合汇总。

## 6. 阶段B：自然错误与恢复诊断

运行冻结的40题×4采样。不强制调用，不插入修复提示，不注入错误。保存所有轨迹，包括不调用、答错、预算结束和解析失败。

错误分类：

- E_PARSE：动作解析失败，不算工具执行错误。
- E_EXEC：代码已送达并执行，发生语法或运行时异常；本轮C主要研究对象。
- E_TIMEOUT：实际代码执行超时，单独报告，不进入本轮C主池。
- E_INFRA：连接失败、服务不可用等基础设施错误，不归因于策略。
- E_MATH：代码成功但数学思路/答案错误，单独标注，不因其失败倒推出E_EXEC。

按全体轨迹报告正确率、不调用比例、有效调用比例、E_EXEC轨迹占比、各种终止和错误类型。另在发生E_EXEC的轨迹中报告后续最终正确率及恢复行为；这些条件性统计不用于宣称错误具有因果影响。

预算耗尽导致无法继续的错误单独计数。缺乏后续机会不能直接标为“有机会却不会修复”。

### 6.1 C的状态选择

候选锚点为某条轨迹第一次自然E_EXEC完成后、下一次模型生成前的状态。

入池条件：可获得完整历史与原始反馈；尚未终止；剩余至少3行动步骤和2工具调用；累计Python时间尚有至少3秒；完整分支上下文可放入模型；执行状态可可靠复原。

每题最多一个锚点：在该题所有合格锚点中按稳定哈希排序选择第一个，不根据后续是否成功、错误是否容易或提示是否有效挑选。最多40个独立题锚点。保存所有候选、排除理由和选中结果。

- 合格锚点≥20题：执行C。
- 8—19题：可以执行C，但标为小样本探索；不作明确支持/否定判定。
- <8题：停止C，输出 `INSUFFICIENT_ERROR_STATES`。不自动扩题或制造错误。

以上门槛是成本与证据可读性的操作约定，不是功效计算。保留错误类型分布，承认该池仅代表当前模型在所选开发任务上产生的、仍有恢复机会的错误。

## 7. 阶段C：同状态三臂续跑

每个锚点、每臂4次续跑。若40个锚点，则480条续跑；A+B+C首轮最多660条轨迹/续跑。A若重跑另加20条。分支不是从题目起点重复解题。

| 臂 | 锚点处模型可见观测 | 作用 |
|---|---|---|
| F：完整反馈 | 冻结协议中真实渲染的原始错误观测 | 基线 |
| P：完整反馈＋提示 | 同一原始观测末尾追加固定提示 | 检查简单改善空间 |
| M：失败标记 | 将本次错误观测的执行输出/错误细节替换为固定失败标记 | 检查详细反馈作用 |

固定提示文本：`The tool execution failed. Inspect the error feedback and your previous code, correct the cause before retrying, and continue solving the original problem.`

固定失败标记：`Tool execution failed.`

保持同一观测消息的role和外层结构；若包装中含预算信息，各臂保留相同预算信息。此前所有消息完全相同。干预只发生一次，后续工具反馈均恢复原协议。提示不提供参考答案、错误修复代码或人工判断。

P与F差异是“有无这条具体提示”，不能泛化成所有提示的效果；M与F差异包含错误细节及长度变化。记录各臂输入长度，不事后挑选提示模板。

### 7.1 分支状态恢复与资源公平

- 从锚点继承原来剩余的行动步数、调用次数、Python时间，不能重置成满预算。
- 保存并核验历史消息、环境事件、计数器和执行上下文；各臂相同锚点状态哈希应一致，观测差异另存。
- 若每次Python调用无状态，验证并记录这一事实；若持久化，采用可靠快照或独立沙箱重建，严禁不同分支共享可变会话。
- 重建所花资源单列为实验恢复开销，不重复扣策略预算。若重放不可确定、依赖外部可变输入且无法复原，则排除并记录，不能伪装为严格配对。
- 同一锚点各臂资源相同；不同锚点剩余资源可不同，配对分析时保持锚点一致。
- 采用固定随机化/轮转执行顺序，避免所有F先跑、所有M后跑造成服务时段混杂。

### 7.2 基础设施失败与续跑规则

为每个逻辑样本设置唯一ID；基础设施故障最多原seed重试一次，保留attempt记录。代码报错、答案错误、解析失败、预算耗尽不重试。

未完成逻辑样本不默默删除或算答错；计为缺失并报告。存在未解决缺失时不标记完整实验；主配对分析仅对完整锚点组进行并报告排除，附缺失结果按正确/错误处理的敏感性范围。基础设施故障率超过2%时暂停排查，不继续批量采样。

## 8. 指标与统计分析

### 8.1 主要指标

锚点后最终正确率：每个锚点每臂4个有效完成样本的正确性均值，再对独立题锚点等权平均。没有最终答案的正常终止计错误；未完成的基础设施故障属于缺失。

预先指定主要配对差异：F−M。次要探索差异：P−F。两者都报告，不按结果交换主次。

按独立题/锚点做配对bootstrap，10000次、固定seed，输出差值及95%区间。每次重采样整组保留三个臂与四次采样；不对全部续跑使用独立伯努利Wilson区间。若按固定层抽样且层内数量足够，采用层内配对重采样并按预先权重汇总；否则明确推断只针对当前诊断池。

少于20个锚点时区间仅作描述性参考。全成功/全失败等退化数据中bootstrap可能给出虚假的零宽区间，应显式标记退化与样本不足，不据此宣称等效或确定性。

本轮不作功效充分性或总体普适性宣称；不能用CI重叠判断等效。若使用“统计显著”措辞，必须处理两个比较的多重检验；更推荐保持探索性差值与不确定性报告。

### 8.2 辅助指标（分母必须明确）

- 下一次工具执行成功：全体分支为分母，无下一次调用计未发生成功；另报告以确实再次调用为分母的条件成功率。
- 原错误被解决：根据执行结果及人工核查判断，不能把换成无关但能运行的代码当作修复。
- 原代码重复：标准化仅做换行和首尾空白规范化，保存规则；精确重复是客观指标，相似代码只作人工分析。
- 同类错误重复：错误类别相同并不一定是相同原因；自动分类与人工确认分开报告。
- 直接作答、不再调用、正常预算结束、解析失败分别计数，不能统称恢复失败。
- 后缀工具调用次数、生成token、推理时延、Python执行时间；同时报告全样本和正确样本的描述性统计，后者有选择偏差。
- B阶段原生错误后的正确率与C固定状态续跑结果分表，不作为独立验证互相重复计数。

### 8.3 人工审计

B中随机抽取最多20条错误轨迹；C中按预先固定规则抽取最多30条分支，并覆盖不同错误类型。核验反馈可见性、错误类别、是否真正修复、最终判定。优先由不了解实验臂的复核者检查；做不到时披露。

对影响主要结论的判定疑点单独审计并给出敏感性结果。不得只挑成功案例，不把模型自动标注当成人工审计。

## 9. 结果判读与研究决策

| 观察 | 允许的结论/行动 | 不允许的推断 |
|---|---|---|
| A不通过 | 当前实现/模型不支持本轮有效诊断，停止 | 反馈无用、RL无效 |
| 自然错误少或合格锚点少 | 当前分布下该切入点覆盖不足，暂不确立 | 所有数学智能体都无此困难 |
| F优于M且结果稳定 | 该状态池中详细反馈具有可利用价值 | 已证明信用分配有缺陷 |
| P优于F | 简单提示存在改善空间，应作为强基线 | 新RL方法必然有效或必要 |
| 所有臂几乎失败 | 可能缺基础能力/资源或错误太难，需要另行诊断 | 直接宣称奖励稀疏是原因 |
| 区间宽、结果混合 | 不确定，按预设范围报告 | 无显著差异就是等效 |
| 修复率提高但正确率不提高 | 局部程序恢复尚未转为任务收益 | 决策能力已全面提升 |

不设事后挑选的“提升5%就成功”门槛；完整报告效应大小、区间、覆盖率、资源与案例。最终建议只能是 `PROCEED_TO_METHOD_STUDY`、`DEPRIORITIZE_RECOVERY` 或 `INCONCLUSIVE`，并附理由；前两者是研究决策，不是统计定理。

若进入方法研究，下一阶段再设计常规RL、恢复状态训练、随机中间状态训练等训练对照及独立测试。本轮不能验证拟议恢复训练方法，也不直接启动该训练。

## 10. 执行实现与验收要求

复用现有runner、事件格式与verifier，必要时新增实验专用前缀续跑入口。不要假定现有AgentLoop.run支持resume，不要通过只重放日志声称重新执行了模型。

必要的有意义测试：

1. 未干预分支恢复：确定性mock模型/工具下，连续运行与断点恢复产生相同后缀事件、用量与最终结果。
2. 预算继承：剩余调用、步骤、时间无重置，终止语义一致。
3. 分支隔离：变量/文件/会话不能跨分支污染；无状态工具也提供验证依据。
4. 干预边界：仅目标观测差异，F保持原文，隐藏标签不进入模型。
5. seed真正传入采样并按请求隔离；记录真实token与长度触顶证据。
6. 数据完整性：唯一ID、阶段样本数、锚点选择、故障重试去重、按题聚合可验证。

CPU/mock测试通过后先跑单锚点分支冒烟，再执行批量。冒烟若使用正式锚点，纳入manifest记录并在协议不变时按既定样本ID复用，不能重复计数或按结果替换。

执行前根据A实测吞吐估算A/B/C总耗时和token量，记入run plan。预设上限为本报告样本量，不因结果不理想自动扩样。模型资产或GPU不可用时交付dry-run检查结果和确切启动命令，不报告已完成模型实验。

## 11. 必须交付的产物

推荐输出根目录：`artifacts/diagnostics/feedback_recovery/<run_id>/`，run_id不得复用覆盖。

```text
protocol.lock.json          # 冻结配置、题池/模型/代码哈希、seed方案

```

每条C记录至少包含：run_id、task_id、anchor_id、source_trajectory_id、arm、sample_index、attempt_id、生成seed序列、模型/协议哈希、前缀与执行状态哈希、干预前后观测、原剩余预算、后缀事件、最终答案/判定、用量、终止原因、基础设施状态。

REPORT必须回答：

1. 本轮实际使用哪个模型、多少独立题、多少有效错误状态？
2. 自然错误的覆盖与恢复情况如何？
3. F−M、P−F各是多少，区间和样本限制是什么？
4. 修复代码是否转化为最终解题收益？
5. 有哪些协议偏离、判定问题、缺失、资源限制？
6. 是否值得进入强化学习方法研究，依据是什么？

完整性验收：主要表格可从原始轨迹重建；统计分母一致；选样可复核；零调用/基础设施故障不能包装成机制阴性；未完成阶段明确标记。交付实际命令与相关代码差异，禁止仅交晨报而不保留原始证据。
